# EKTAtestTask — LED Screen Monitor

Тестовий desktop-застосунок: імітація моніторингу LED-екрана, що складається з кабінетів, а кожен кабінет — з модулів. Для кожного модуля відображається температура, а при виборі модуля — детальна інформація про нього в окремій панелі.

> 📄 Повний текст технічного завдання — у файлі [TASK.md](./TASK.md).

## Технології

- .NET 10 / C#
- WPF (`UseWPF`)
- CommunityToolkit.Mvvm 8.3.2 (`ObservableObject`, `[ObservableProperty]`, `[RelayCommand]`, `ObservableValidator` для валідації)

## Структура проєкту

```
EKTAtestTask/
├── Models/
│   ├── ScreenModel.cs      # параметри екрана (кількість кабінетів, їх розмір, кількість модулів)
│   ├── CabinetModel.cs     # кабінет: позиція + список модулів
│   └── ModuleModel.cs      # модуль: позиція, температура, DisplayId
├── ViewModels/
│   ├── BaseViewModel.cs        # базовий клас (ObservableValidator)
│   ├── ScreenViewModel.cs      # головна VM: параметри, побудова екрана, таймер, вибір модуля
│   ├── CabinetViewModel.cs     # обгортка над CabinetModel зі списком ModuleViewModel
│   └── ModuleViewModel.cs      # обгортка над ModuleModel: колір за температурою, тултип, розмір у px
├── Services/
│   └── TemperatureService.cs   # генерація випадкової температури
├── Converters/
│   ├── TemperatureToColorColorConverter.cs  # температура → колір індикатора (для панелі деталей)
│   └── NullToVisiblyConverter.cs            # null → Visibility (показ/приховання панелі деталей)
├── MainWindow.xaml(.cs)     # UI: панель параметрів, сітка кабінетів/модулів, панель деталей, статус-рядок
└── App.xaml(.cs)
```

Архітектура відповідає патерну MVVM: `Model` — чисті дані, `ViewModel` — стан і команди (`CommunityToolkit.Mvvm`), `View` (XAML) — прив'язки без коду обробки логіки в code-behind (крім `InitializeComponent()`).

## Функціонал

**Параметри екрана**, що задає користувач у верхній панелі:
- кількість кабінетів по X та Y (`CabinetsX`, `CabinetsY`, діапазон 1–20);
- розмір кабінету в пікселях, ширина/висота (`CabinetPixelWidth/Height`, 40–400 px);
- кількість модулів у кабінеті по X та Y (`ModulesX`, `ModulesY`, діапазон 1–16).

Кожне поле має валідацію (`[Range]` + `ObservableValidator`), некоректне значення підсвічується червоною рамкою, а кнопка «Побудувати» блокується, поки є помилки.

**Після побудови екрана програма:**
- будує візуальну сітку кабінетів, кожен з яких містить сітку модулів (`ItemsControl` + `UniformGrid`/`WrapPanel`);
- показує температуру на кожному модулі (число на плитці + тултип з повною інформацією);
- підсвічує модуль кольором залежно від температури (синій / зелений / жовтий / червоний за порогами 30/55/75 °C);
- при кліку на модуль — виводить детальну інформацію (ідентифікатор кабінету/модуля, розмір модуля в px, точну температуру, кольорову легенду) в правій панелі.

Перебудова відбувається по кнопці «Побудувати» (`BuildScreenCommand`).

**Дані:** температура генерується випадковим чином при побудові екрана (`TemperatureService.Generate`).

## Реалізовані додаткові вимоги («плюси»)

- ✅ **Періодична зміна температур по таймеру** — кнопка «Старт/Стоп таймера», оновлення кожні 2 секунди (`DispatcherTimer`) для всіх модулів одразу, з оновленням панелі деталей, якщо модуль вибраний.
- ✅ **Коректна поведінка при зміні розміру вікна** — вікно має `MinHeight`/`MinWidth`, вміст екрана обгорнутий у `ScrollViewer` з `WrapPanel`, тому кабінети перетікають і скролюються при зменшенні вікна.
- ⚠️ **Avalonia** — не реалізовано, використано WPF (обидва варіанти допустимі за умовами ТЗ).

## Як запустити

Потрібен .NET 10 SDK з підтримкою Windows Desktop.

```bash
git clone https://github.com/coutAndrii16/EKTAtestTask.git
cd EKTAtestTask
dotnet run
```

Або відкрити `EKTAtestTask.sln` у Visual Studio та запустити проєкт (F5).
